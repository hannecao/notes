# 单章流程

你是编排者和责任编辑，不是正文作者。正文由 GLM 写；你检查细纲、组 prompt、审稿、做小修、落盘、更新状态。

## 0. 每章开新会话

上一章的对话不带进来。需要的信息都在文件里。

## 1. 只读这些

| 内容 | 上限 |
|---|---|
| `00_设定/固定设定.md` | 3000 字 |
| 本章出场人物的卡 | 每人 500 字 |
| `02_状态/近况.md` | 1500 字 |
| `02_状态/伏笔账本.md` 中细纲点名的条目 | — |
| `01_规划/细纲/chXXX.md` | 1500 字 |
| `01_规划/卷N_节奏表.md` 中本章前后各 2 行 | — |
| `样章.md` | 2000 字 |
| 上一章正文最后 800 字 | 800 字 |

不读其他章节正文、`04_归档/`、整个人物目录。确实需要查某个旧细节时，用 grep 搜关键词，只看命中的几行。

## 2. 检查细纲，不合格不写

- 每个场景都填了：想要什么、谁在阻拦、转折、要写细的画面。
- 有“读者最想看到的一幕”。
- 节奏位置和节奏表一致。

不合格时，把缺的项列给用户，补好再继续。细纲补全是规划工作，可以提建议，但要用户确认。

## 3. 组 prompt，调用 GLM

按 [GLM-prompt模板.md](GLM-prompt模板.md) 填写，存到 `work/chXXX_prompt.md`。调用 GLM，原稿存到 `work/chXXX_raw.md`。

## 4. 审稿

按 [审稿表.md](审稿表.md)：

- A 类（查错）：直接改。
- B 类（查好看）：不合格就退回 GLM。**不要自己扩写，也不要靠删减来救。**
- 改动超过 10%，或 B 类有 2 项以上不合格：把问题写进 prompt 的要求里重新调用 GLM，最多 2 次。2 次还不行，说明细纲有问题，回到第 2 步找用户。

## 5. 落盘并更新状态

更新状态时是**替换**，不是追加。

1. 正文存到 `03_正文/chXXX.md`。
2. `近况.md` **整体重写**，不超过 1500 字。“最近发生”只保留最近 3 章；挤出去的内容追加到 `04_归档/近况历史.md`。
3. `伏笔账本.md`：新埋的加进去，推进的改层级，收回的移到 `04_归档/已收伏笔.md`。
4. 人物卡：只改“当前”部分里变了的那几行。
5. 节奏表：标记本章完成。

## 6. 每 10 章体检

运行 `python novel-kit/scripts/check.py <书名> 10`，然后：

- 有文件超上限：压缩或归档。
- 最近几章的概括词密度明显高于样章，或对话占比明显低于样章：文风在变平，下一章的 prompt 里加强对应要求。
- 看节奏表：连续 3 章以上是“喘息”时，提醒用户调整后面的规划。

## 硬规则

- 不经要求不自己写整章。
- 不新增细纲之外的人物、设定、能力、专名、异象。
- 伏笔只写到细纲标注的层级。
- 主角亲自完成本章的核心判断和选择。
